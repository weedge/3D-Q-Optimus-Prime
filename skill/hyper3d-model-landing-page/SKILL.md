# Hyper3D Model Landing Page

## Purpose

This skill covers the full pipeline from a visual reference to a runnable 3D showcase. It includes a Python asset-generation script plus the implementation rules for integrating the resulting GLB into an existing or new frontend.

The two Python scripts separate reference-image generation from 3D-model generation. `generate_reference_image.py` handles OpenAI image generation; `generate_hyper3d_model.py` handles local/URL image preparation, Hyper3D Rodin submission, polling, model download, optional BANG splitting, and optional copying into a project's `public/` directory. The agent handles the visual landing page and browser verification.

## Inputs and Outputs

Supported reference inputs for the model script:

- A local raster image: `--image-path path/to/reference.png`
- An image URL: `--image-url https://example.com/reference.png`
- An image generated by the companion script, passed as `--image-path`

Typical outputs under the selected artifact directory:

- `reference.*`: the reference used for generation
- `rodin-submit.json`: submitted task metadata without secrets
- `rodin-result.json`: completed task response
- `model.glb`: downloaded base model
- `bang-result.json` and `model-exploded.glb`: optional split result
- `model-manifest.json`: paths, task IDs, and page integration metadata

When `--project-dir` is supplied, the final model is copied to `<project-dir>/public/` and a manifest is written beside it. Do not overwrite an existing model without an explicit `--force`.

## Quick Start

From this skill directory, install the Python dependencies:

```bash
python3 -m pip install -r requirements.txt
```

Generate a reference image with OpenAI:

```bash
OPENAI_API_KEY="$OPENAI_API_KEY" \
python3 scripts/generate_reference_image.py \
  --prompt "A full-body Q-style robot product render, front three-quarter view, centered, clean silhouette, complete feet" \
  --output ./artifacts/robot/reference.png
```

Send the generated image to Hyper3D and split it into parts:

```bash
HYPER3D_API_KEY="$HYPER3D_API_KEY" \
python3 scripts/generate_hyper3d_model.py \
  --image-path ./artifacts/robot/reference.png \
  --prompt "Full-body Q-style robot with distinct head, arms, torso, legs and feet, polished painted metal, web-ready 3D asset" \
  --bang \
  --bang-instruction "Split into 8 readable symmetric parts: head, left arm, right arm, left chest, right chest, core torso, left leg and foot, right leg and foot" \
  --out-dir ./artifacts/robot
```

`generate_reference_image.py` requires `OPENAI_API_KEY`. `generate_hyper3d_model.py` requires `HYPER3D_API_KEY`. Never put either key in source files, manifests, prompts, logs, or frontend code.

## Workflow

### 1. Resolve the image

Run one of the following reference paths, then pass its output to the model script:

- Validate local files as non-empty raster images.
- For URLs, use a bounded download, check the HTTP status and content type, and reject HTML or zero-byte responses.
- For OpenAI generation, use `generate_reference_image.py` with the Images API through the official Python SDK. The script defaults to `gpt-image-2`; keep the model configurable with `--model`.
- Ask for a full-body, centered reference when the target is a character or robot. Explicitly mention feet and lower geometry to avoid head-only results.
- Treat generated images as visual references, not proof of an official character, product, or licensed design.

### 2. Generate with Hyper3D Rodin

The script calls the Hyper3D v2 Rodin HTTP API with a multipart image upload and JSON options. Defaults are web-friendly: GLB output, `Quad` mesh mode, and a configurable medium quality tier. Adjust `--tier`, `--mesh-mode`, `--quality`, and `--geometry-format` only when the user asks for a different tradeoff.

The base task must complete before any split operation. Poll with the server's `jobs` status endpoint and respect `Retry-After`. Do not resubmit after a timeout; save the task response and report the task ID so it can be resumed.

### 3. Split with BANG when requested

Use `--bang` only after the base Rodin task is complete. Pass the requested part count and a concrete semantic decomposition through `--bang-instruction`. For symmetric robots, prefer paired left/right groups and a centered core. Do not claim that an exploded view is real if the result is one undivided mesh.

The script downloads the BANG result when the API returns a model URL. If the API returns only a result page or a response shape the script cannot identify, it preserves the raw JSON and reports the manual result URL instead of guessing a file.

### 4. Integrate into the landing page

Inspect the existing project before scaffolding. Reuse the current framework, dependencies, visual language, and page template. For React/Vite, use the existing React Three Fiber and Three.js setup when available.

Use `GLTFLoader` to load the generated GLB from `public/`. Traverse the scene and inspect actual group/mesh names before creating the index. Never assume `root0`, `root1`, or a fixed part order without confirming the asset hierarchy.

The viewer should:

- Load the actual GLB with a visible loading and error state.
- Fit the camera from the combined bounding box of all visible meshes in both assembled and exploded states.
- Keep the entire model in frame, including feet and the lowest geometry.
- Store one mapping containing index label, display name, color, node/group name, base transform, and exploded target.
- Interpolate each part from assembled to exploded transforms with a continuous progress value and damping/easing.
- Use mirrored left/right target offsets where appropriate and keep the centerline stable.
- Highlight the exact selected node/group when an index item is clicked; do not highlight an arbitrary proxy group.
- Support orbit drag, bounded wheel/pinch zoom, reset, and any controls requested by the user.
- Keep the final exploded parts separated enough to read visually; if parts overlap, inspect coordinate spaces and parent transforms before changing camera scale.

For a product-style page, include a concise hero title, a visual interaction prompt, a structure index, an assembled/exploded progress control, and an information panel. Use references only for visual direction; do not copy proprietary text, artwork, or layout assets verbatim.

### 5. Add factual information carefully

If the page introduces a character or product, research current authoritative information before writing factual copy. Add source links to the page and distinguish public facts from AI-generated interpretation. For copyrighted characters, label the generated asset as a non-official visual study unless the user provides rights or asks for a licensed workflow.

### 6. Verify and deliver

Run the project's existing build command, normally `npm run build`. Then verify:

- The page and model asset return HTTP 200.
- Assembled view shows the complete object, including feet.
- Moving the slider visibly expands every requested part over time.
- Each structure-index item selects the matching physical part.
- The page has no new console errors.
- The information panel, timeline, and interaction hint do not overlap at desktop and mobile widths.
- The final model path, permanent Hyper3D result page, and generated reference path are recorded in the handoff.

## Python Script Contracts

### `generate_reference_image.py`

Run `scripts/generate_reference_image.py --help` before extending the image script. Important options:

- `--prompt`: OpenAI reference-image prompt
- `--output`: PNG output path
- `--model`, `--size`, `--quality`: OpenAI Images API settings

### `generate_hyper3d_model.py`

Run `scripts/generate_hyper3d_model.py --help` before extending the model script. Important options:

- `--image-path`, `--image-url`: mutually exclusive reference sources
- `--prompt`: Hyper3D model description
- `--out-dir`: artifact directory
- `--project-dir`: optional frontend project to receive the final GLB
- `--bang`: run the BANG split after base generation
- `--bang-instruction`: semantic split guidance
- `--tier`, `--mesh-mode`, `--quality`, `--geometry-format`: Rodin generation settings
- `--poll-timeout`: bounded wait in seconds
- `--force`: allow replacement of an existing project asset

The scripts use `urllib` for image downloads, the OpenAI Python package for image generation, and Requests for Hyper3D calls. They write redacted JSON metadata and never serialize API keys. They are responsible for asset preparation, not for editing React source files; the agent should use the manifest and current page template to implement the viewer.

## Common Failure Modes

- **Head-only result**: the reference or prompt was cropped. Regenerate with explicit full-body language and a centered silhouette; do not hide missing geometry with camera zoom.
- **Feet missing in the viewer**: the camera was fitted to a partial node. Recompute bounds across all meshes and exploded targets.
- **Parts twist or overlap**: transforms were applied in mixed local/world spaces. Normalize the parent hierarchy, preserve each node's base transform, and calculate symmetric targets in one coordinate space.
- **Index does not match the model**: node mapping was guessed. Inspect the actual scene hierarchy and bind each label to a confirmed group.
- **No visible explosion**: the page toggles state without interpolating transforms, or all pieces are one mesh. Use BANG independent parts or explain that an actual split is unavailable.
- **Image upload blocked**: preserve the source and error response, then ask the user to upload the image through Hyper3D's hosted flow rather than pretending the model job started.
- **Generation was charged but finalization failed**: use the returned recovery/result URL and import the recovered file; do not spend credits by resubmitting the same generation.
