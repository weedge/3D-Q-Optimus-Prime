# HyperFrames 3D 展示视频

## 目标

将已有的 3D 展示页、GLB/BANG 模型和品牌视觉规范，编排为可渲染、可复核的产品/角色展示视频。默认同时规划横版和手机竖版，但两种画布使用独立布局，不要简单缩放同一套坐标。

## 输入检查

开始前检查：

- `DESIGN.md` 或 `visual-style.md`：确定背景、颜色、字体、运动规则和禁用风格。
- 3D 模型：优先使用真实 GLB；若需要部件拆解，确认模型来自真实 BANG/拆分结果，而不是仅靠 CSS 假位移。
- 展示页来源：确认完整形态、部件层级、当前网页视觉效果和可用素材。
- 权威网站资料：用户要求“与网站一致”时，先访问指定官网或项目 README，使用页面实际信息，不凭记忆补写；在视频中保留来源名称或链接。
- 目标画布：横版通常为 `1920×1080`，竖版通常为 `1080×1920`；确认帧率和总时长。

如果模型层级、部件数量或网页资料无法确认，先检查源文件和网站，不要猜测部件名称、顺序或介绍内容。

## 内容结构

推荐叙事顺序：

1. 标题/身份建立：产品或角色名称、简短定位和档案状态。
2. 角色/产品介绍：只放已核验的网页信息；必要时补充“本视频为 AI/研究模型”的免责声明。
3. 完整形态：先展示组装完成的 3D 模型，允许缓慢旋转，确保头部、身体、腿脚均可见。
4. 对称爆炸总览：沿中心轴展开所有部件，保持左右镜像关系和网页中的爆炸效果一致。
5. 部件详情：每个部件使用独立时间段和独立介绍卡；介绍当前部件时，在上方完整形态中高亮对应部位，下方展示该部件的放大旋转模型。
6. 片尾：展示最终图片/海报、项目名称、GitHub 或官网地址、感谢观看。

对于 8 部件机器人，可采用头部、左/右肩臂、左/右胸甲、核心躯干、左/右腿脚等语义分组；必须以实际 GLB 节点为准。左右对称部件应分别有自己的时间段、标签和高亮状态。

## HyperFrames 编排规则

- HTML 是视频源文件，使用 `data-width`、`data-height`、`data-duration` 或项目现有的 HyperFrames 约定声明规格。
- 先写静态终态布局，再加入 GSAP 进入、退出和连续旋转动画。
- 使用 `window.__threeMotion` 或等价状态统一驱动 `explode`、`activeIndex`、`rotationY`、当前详情部件和透明度；不要让 DOM 文案和 Three.js 状态各自维护一套时间轴。
- 让模型加载后再渲染有效画面；模型未加载时保持安全背景，不要输出破碎或错误的几何体。
- 使用真实节点映射：先读取 GLB 顶层组/节点名称，再建立部件数组；不要按数组下标盲猜模型结构。
- 完整形态和爆炸形态使用连续插值，爆炸目标以中心轴镜像计算；不要把爆炸描述写成“拆散”，除非用户明确要求拆散。
- 部件高亮应同时保留完整轮廓：选中部件使用对应色和较高发光，未选部件保持足够透明度与亮度，不能全部变成黑色或不可见。
- 详情阶段用两个 3D 视口：上方完整组装形态，下方当前独立部件。视口使用正确的 WebGL scissor/viewport 坐标，注意 WebGL 原点在左下而 CSS 原点在左上。
- 上方总览相机必须适配宽视口的纵向视场；检查雾效 `near/far`，避免拉远相机后完整模型被雾完全遮盖。

## 横版布局

横版优先突出网页式左右分栏：

- 左侧放标题、介绍、部件说明和结构索引。
- 右侧放完整形态、爆炸总览或独立部件；模型区域保持足够宽度。
- 介绍卡和模型卡使用明确边界，避免文字压到模型关键结构。
- 片尾地址可放在中心或左下安全区，但不要靠近播放器控制条区域。

横版也必须按部件独立停留，当前部件的说明与模型视图在同一时间段内同步切换。

## 竖版布局

竖版不是横版的等比缩放，使用上下分区：

- 完整形态阶段：介绍卡高度只包住标题和实际介绍文字，卡片下方单独留出完整 3D 模型区域；卡片不得覆盖模型。
- 部件阶段：上方先展示完整擎天柱，当前部件用高亮强调；介绍文字放在上方卡片中；下方卡片只展示当前独立部件的放大模型。
- 上方完整模型要通过远景相机、合理模型缩放和足够亮度保证整身可见；不得只剩头部或一个高亮零件。
- 下方独立部件模型允许更大比例和缓慢旋转，但必须留出边距，不能裁切主体。
- 预留底部安全区，避免手机播放器进度条遮住项目地址、感谢观看或模型脚部。
- 竖版文字可适当放大、增加行高，但不要让介绍卡扩展到模型区域；正文结束后保留少量呼吸空间即可。
- 不在左下角堆叠 `00-01`、`01-02`、`02/08` 等步骤编号；除非用户明确需要进度导航，否则只显示部件名称、中文说明和结构元数据。

## 文字与资料

- 网站一致性优先于文案润色：先复制事实，再做长度适配，不要改变角色身份、阵营、来源、功能或项目技术栈信息。
- 中英文名称可并列，但不要用未经来源确认的别名。
- 资料卡中可以写“AI 生成/视觉再创作/研究模型”等限定语，避免让观众误以为是官方模型。
- 片尾项目描述应准确保留项目使用的 React、Vite、Three.js、React Three Fiber、完整形态、8 部件爆炸视图和结构高亮等信息；地址使用用户给出的原始 URL。

## 时间轴模板

按总时长调整，但保持以下关系：

- 标题与完整形态阶段：先静态建立，再进行一次缓慢旋转。
- 爆炸总览：在说明卡可读后开始展开，完成后至少留出一个稳定镜头。
- 每个部件详情：进入动画 → 稳定展示 → 独立模型旋转 → 退出动画；切换部件时先更新 `activeIndex`，再切换说明卡，避免文字与高亮错位。
- 片尾切换前先淡出爆炸视图，片尾图片、地址和感谢观看至少保持一个完整可读停留段。

动画建议使用 `power2`、`power3`、`sine` 或 `expo` 缓动；旋转特写使用 `ease: 'none'` 或平滑线性旋转，避免抖动和突然倒转。

## 验证流程

完成 HTML 后按以下顺序验证：

1. 运行 `npx hyperframes check <project-dir>`，确认 `Runtime`、`Motion`、`Contrast` 没有错误。
2. 运行 HyperFrames MP4 渲染，明确指定画布对应的帧率、质量和 GPU 模式。
3. 使用 `ffprobe` 核对输出的宽高、帧率、时长和音频状态。
4. 用 `ffmpeg` 抽取至少以下时间点：完整形态、爆炸总览、第一个部件、中间部件、最后一个部件、片尾。
5. 逐帧确认：
   - 完整形态没有被介绍卡遮挡；
   - 头部、身体和腿脚全部可见；
   - 当前部件高亮准确，未选部件仍可辨认；
   - 上方完整形态与下方独立部件没有错位或重叠；
   - 每个独立部件都单独出现并能旋转；
   - 文字没有被模型、卡片边界或手机进度条覆盖；
   - 片尾图片、地址和感谢观看完整显示。

如果只看到高亮部件而看不到完整形态，优先检查：详情主视口的 scissor 坐标、相机纵向视场、模型组缩放、材质透明度和场景雾效范围。修复后必须重新渲染，不要只依赖 HTML 预览截图。

## 交付

交付时说明：

- 横版和竖版源 HTML 的绝对路径；
- 最终 MP4 的绝对路径与规格；
- 已核验的官网/项目资料来源；
- HyperFrames 检查结果；
- 抽帧核对过的关键时间点；
- 未修复的仅有警告（例如场景交叉淡入或文件体积提示），不要把警告描述成错误。

除非用户另有要求，不要提交 Git、创建分支、安装 Skill 或修改全局技能目录。
